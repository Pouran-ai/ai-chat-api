# AI Chat API

A RESTful chatbot API built with **FastAPI**, powered by a locally hosted **Qwen 2.5 (3B)** language model through Ollama.

This project demonstrates how to build an AI-powered chat API with request validation, SQLite conversation storage, error handling, and local LLM integration.

## Features

- Chat endpoint powered by a local Qwen model
- Local AI inference using Ollama
- Request validation using Pydantic
- Persistent conversation history using SQLite
- Separate conversation history for each user ID
- Retrieve previous messages and provide conversation context
- Delete conversation history
- HTTP error handling for Ollama and database operations
- Non-streaming responses

## Technologies

- Python 3.12
- FastAPI
- Pydantic
- Requests
- Uvicorn
- SQLite
- Ollama
- Qwen 2.5 (3B)

## Requirements

- Python 3.12 or compatible version
- Ollama installed and running
- Qwen 2.5 (3B) model downloaded locally

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/Pouran-ai/ai-chat-api.git
cd ai-chat-api
```

### 2. Create and activate a virtual environment

On Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Install and configure Ollama

Download and install Ollama:

https://github.com/ollama/ollama/releases

Make sure Ollama is running.

### 5. Download the Qwen model

```powershell
ollama pull qwen2.5:3b
```

Verify that the model is available:

```powershell
ollama list
```

## Running the API

Start the FastAPI development server:

```powershell
python -m uvicorn test:app --reload
```

The API will be available at:

```text
http://127.0.0.1:8000
```

Interactive API documentation:

http://127.0.0.1:8000/docs

## API Endpoints

### 1. Chat with AI

**POST /chat**

Send a message to the AI assistant.

Example request:

```json
{
  "user_id": "user123",
  "message": "Hello! Can you help me learn Python?"
}
```

Example response:

```json
{
  "reply": "Of course! I can help you learn Python.",
  "status": "success"
}
```

The actual response is generated by the locally running Qwen model.

### 2. Delete conversation history

**DELETE /chat/{user_id}**

Delete all stored messages belonging to a specific user ID.

Example:

```text
DELETE /chat/user123
```

Example response:

```json
{
  "message": "Chat history deleted successfully.",
  "status": "success"
}
```

If no conversation history exists for the specified user ID, the API returns HTTP 404.

## Database

The project uses SQLite to persist conversation history.

The database file `chat_history.db` is created automatically when the application starts.

Messages are stored with the following fields:

- `id`: Unique message identifier
- `user_id`: Conversation owner identifier
- `role`: Message role (`user` or `assistant`)
- `content`: Message content

Conversation history is retrieved from SQLite and included in subsequent requests to provide context to the AI model.

## Error Handling

The API handles several types of errors:

| HTTP Status | Description |
|---|---|
| 422 | Invalid request data |
| 404 | Conversation history not found |
| 500 | Database error |
| 502 | Invalid response or communication error |
| 503 | Ollama connection error |
| 504 | Ollama request timeout |

## Current Limitations

- The API uses `user_id` to separate conversations, but it does not implement authentication or authorization.
- The API is intended for local development and educational purposes.
- Responses are non-streaming.
- Ollama must be running locally for the chat endpoint to work.
- No production deployment or advanced security configuration is included.
